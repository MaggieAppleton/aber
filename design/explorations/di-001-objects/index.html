DI-001 · Telling objects apart

“There are a lot of issues with being able to tell the difference between different objects. Sometimes there's an inconsistent display of objects within the system. If you look at the interface grammar material in this repo, we have a clear set of nouns and verbs defined, but they don't always show up consistently in the interface, which is a problem.”Maggie

The model gives each object type one icon (Dump, Signal, Theme, Theory and Prototype). A Theory still appears in about nine forms, and only some of them carry its Target glyph. The same Target also stands for "drafts" in general. The question is not "add the icon everywhere". The question is which rule decides when a reference must say its type, and what form it says it in.

Out of scope here (owned by di-006-markers): freshness and challenge markers, and the prototype status colours. They are left exactly as they are in every context below.

Three strategies

These are rules, not skins. A decides how a type is marked: always, with the same glyph. B decides it by giving each type a form. C decides when to mark: only where the surrounding container leaves the type ambiguous.

1 · Theory pane: the densest mixed context

A theory references a theme, a rival theory, signals (as evidence), and, inside an unfolded signal, another theory, a theme and its dump. It also references theories it follows from or leads to, and its prototypes. Today the same theory reference appears as four chip variants with three different glyphs.

2 · Columns: a homogeneous context

Each column header already names its type. This is where an "always mark" rule costs the most and earns the least.

3 · Briefing and the dump log: mixed lists and the draft count

The Drafts group mixes theories, a theme and a prototype. The flow line and the dump log use Target to mean "drafts of any type", which teaches the wrong meaning for Target.

4 · Sidebar and Theme section

The sidebar lists themes with no header and no glyph, and lists prototypes under a PencilRuler header, each with a plain PencilRuler (status lost). In the Theme section a theme is a bold heading and its theories are cards.

5 · Chat: objects inside prose

Chat shows any type the assistant mentions, in the order it mentions them. Today a theory is the only card without an icon, so it is the hardest one to identify there.

6 · States: rest, hover, focus, selected, draft

A theory reference in its chip form and a signal in its row form. Hover and focus are forced so they can be compared side by side. Check that the type mark survives every state, especially the dashed draft.
